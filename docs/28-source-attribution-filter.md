# 28. 来源标注过滤机制（Source Attribution Stripping）

## 28.1 背景

科技资讯发帖流程（`run_tech.py`）按发帖者角色生成第一人称文案时，
原始模板会在文案中嵌入来源标注（如"來源 36氪"、"via TechCrunch"、
"【IT之家】"等），这会暴露内容为转载而非原创分享，降低真实感。

本机制的目标：**按发帖者角色发布时，自动过滤掉所有来源/出处标注**，
使文案看起来像用户自己原创的科技观点分享。

## 28.2 过滤规则

`strip_source_attribution()` 函数实现以下 6 层过滤：

### 规则 1：中文圆括号内来源

```
（來源 36氪）  →  移除
（來源：IT之家）  →  移除
（来源 XX）  →  移除
```

正则：`[（(]\s*[來来]源\s*[:：]?\s*[^）)]+[）)]`

### 规则 2：英文圆括号内 via/source/sumber

```
(via TechCrunch)  →  移除
(via: XX)  →  移除
(source: XX)  →  移除
(sumber: XX)  →  移除
(出典 XX)  →  移除
```

正则：`\(\s*(?:via|source|sumber|出典|स्रोत|সূত্র)\s*[:：]?\s*[^)]+\)`

### 规则 3：中文方括号来源前缀

仅匹配已知站名（SITE_CN 注册的所有来源），避免误伤正文方括号：

```
【36氪快訊】  →  移除
【IT之家】  →  移除
【BBC中文】  →  移除
```

### 规则 4：行内 via/來源/出典 + 站名

不在括号内的来源标注：

```
來源 36氪  →  移除
via TechCrunch  →  移除
出典 Gizmodo日本  →  移除
sumber: 8世界  →  移除
```

### 规则 5：引述短语

```
摘自XX  →  移除
reported by XX  →  移除
dilaporkan oleh XX  →  移除
——XX報導  →  移除
XX reports  →  移除
```

### 规则 6：清理残留

- 多余空格合并
- 空括号 `()` `（）` `【】` 移除
- 连续标点归一（`，，` → `，`）
- 句首残留标点清除

## 28.3 模板设计原则

从 v2 开始，`LANG_TEMPLATES` 中的文案模板**不再包含 `{site}` 和 `{via}` 占位符**：

**旧模板（v1，已废弃）：**
```python
"【{site}】{title}——以從業者角度看..." 
"科技快訊｜{title}（{via}：{site}）。身為數碼控..."
```

**新模板（v2，当前）：**
```python
"{title}——以從業者角度看，這條資訊值得關注..."
"科技快訊｜{title}。身為數碼控，這個我必須先收藏..."
```

`strip_source_attribution()` 作为**双保险**机制存在：
- 主要靠模板本身不包含来源
- 过滤函数兜底处理标题中可能残留的来源标注（如采集标题本身带"36氪"字样）

## 28.4 覆盖语言

过滤机制覆盖所有 7 种发帖语言：

| 语言 | via 关键词 | 示例过滤 |
|------|-----------|----------|
| zh_hant | 來源 | （來源 36氪） |
| en | via | (via TechCrunch) |
| ja | 出典 | （出典 Gizmodo日本） |
| ms | sumber | (sumber: 8世界) |
| id | sumber | (sumber XX) |
| hi | स्रोत | (स्रोत XX) |
| bn | সূত্র | (সূত্র XX) |

## 28.6 集成位置

- **函数定义**：`scripts/run_tech.py` → `strip_source_attribution()`
- **调用点**：`build_caption()` 函数内，模板 `.format()` 之后、去重检查之前
- **文档**：`docs/28-source-attribution-filter.md`（本文件）

## 28.7 与其他过滤机制的关系

| 机制 | 过滤目标 | 作用阶段 |
|------|---------|---------|
| `docs/11-anti-ad-filtering.md` | 广告/商业素材 | 采集阶段（素材入库前） |
| `docs/20-dedupe.md` | 重复内容 | 采集/发布阶段 |
| **本机制** | 来源/出处标注 | 文案生成阶段（发布前） |

三者互不冲突，按流水线顺序执行。
